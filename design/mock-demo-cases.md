# 用例执行详情 · Trace 演示数据（独立特性）

本文件服务于「用例执行详情 · 对话轮次 / 判分 / 追问自检 / 证据」这一版界面变更。该变更会重构原有的操作路径，因此作为**独立特性**开发：

- 分支：`feature/case-trace-v2`（UI、数据契约、演示数据都在此分支）；
- 演示通道：mock 后端 `127.0.0.1:8877` + 演示前端 `127.0.0.1:5174`，与常规前端 `5173`、真实后端 `8000` 完全隔离；
- 演示 ID 段：任务 `900101` / `900102`，执行 `900001`–`900009`，用例 `900211`–`900227`。**不再复用真实执行 ID**（真实库里 6580–6588 是同号记录，旧演示数据会与真实数据同名混淆，已全部迁出）。

## 1. 启动与访问

```powershell
# 0) 切到特性分支
git switch feature/case-trace-v2

# 1) mock 后端（127.0.0.1:8877）
node design/mock-trace-server.cjs

# 2) 演示前端（127.0.0.1:5174，/api 代理到 8877）
cd frontend
npx vite --config vite.mock.config.ts
```

登录任意账号密码（mock 返回固定令牌 `mock-token-demo`）。

- 直接落判分页：`http://127.0.0.1:5174/trace?execution=900004&tab=judge`
- `tab=judge` 只选顶部页签；抽屉里的「判定」段需要先展开轮次行，再点「评分详情」。
- 多轮：先点判分矩阵行展开，再点「评分详情」；单轮：行默认展开，直接点「评分详情」（再点行会折叠）。
- 任务详情可回跳：mock 已实现 `/api/v1/tasks/:id`、`/metrics`、`/executions`、`/retry-candidates`，从执行页点「返回批量任务详情」或任务编号进入 `900101`（2 条用例）/ `900102`（7 条用例），列表「查看结果」可回到对应执行。

## 4. 字段自洽约束

- 四维合计 = `total_score`（LEGACY）；`judge_result.dimension_scores` 与 `judge_rows[].dimension_scores` 同步。
- `judge_result.threshold` / `case_snapshot.pass_threshold` 字面一致；900004 故意保留用例阈值 80，用来区分「用例阈值」与「执行阈值」。
- 规则检查 `passed`、`rule_result.passed`、`judge_result.policy_notes`、`pass_flag` 四者一致：硬门槛失败时 `pass_flag=false` 且 `policy_notes` 说明原因。
- 契约记录：`judge_result.gates` 与 `answer_grading.gates` 一致；`answer_grading.total_score` 是契约排名分，`quality.total_score` 是四维质量分（仅参考）。
- 时间线：`started_at + 各轮 latency + 裁判耗时 ≈ finished_at`；`ttft_ms` 单轮 = 该轮 TTFT，多轮 = 各轮均值。
- 任务统计与用例集合一致：900102 = 7 个用例，通过 3（900005 / 900007 / 900008）、失败 4（900003 / 900004 / 900006 / 900009），`enable_self_check=false`。

## 5. 与真实数据的边界（不得编造）

- 真实 `turn_trace` 表**没有**轮次级 `judge_score / dimension_scores / fact_results / judge_reason / contract_*` 列，mock 也不造这些字段；裁决卡的四维一律来自执行级 `judge_result`，并标注口径。
- 真实库 472 条轮次的 `tool_calls / evidence` 均为 JSON `null`，所以真实数据的「调用链」只能空态；mock 的 SSE 轮次才有 `tool_calls`，用于演示有数据形态。
- 历史 RUBRIC 记录（900008）有 `total_score / pass_flag`，没有 `turn_trace / judge_result / answer_grading`，因此判分页只能给执行级结论。
- 0 轮记录不渲染判分矩阵与「判定口径」，避免 0 轮空表格。
