# 用户管理 · 界面方案对比

> 可交互对比稿：[`docs/design/user-management/user-designs.html`](./design/user-management/user-designs.html)
>
> 打开后可在顶部切换 A / B；点击用户行可切换详情，方案 B 支持关闭 / 打开右侧抽屉。
>
> **当前已采用方案 B「表格 + 侧滑抽屉」**，并合入主界面 `ui-design.html`；方案 A 保留作为小团队快速维护的备选。

---

## 改版前的问题

现有用户管理页是「表格 + 下方访问控制面板」：

1. 窄屏下表格和详情上下堆叠，点一个用户后要往下滚才能看到角色。
2. 角色勾选、权限摘要、会话提醒都挤在详情里，纵向很长。
3. 新建/重置密码/禁用等操作分散在表格行和详情面板，主操作不够集中。
4. 账号数量增长后，表格列会继续变密，详情面板也会越来越长。

下面两套方案分别解决「小团队快速维护」和「账号增长后的扩展性」。

---

## 方案 A：主从列表（备选：小团队）

![方案 A：主从列表](./design/user-management/user-a.png)

**结构：**

- 左侧紧凑用户列表：搜索、状态筛选、角色/状态摘要。
- 右侧固定详情：基础信息、角色勾选、生效权限、最近活动。
- 左下增加「登录安全」卡片：会话有效期、失败锁定、密码哈希策略。

**优点：**

- 选中用户后详情始终在右侧，不需要打开/关闭抽屉。
- 列表只保留姓名、用户名、角色和状态，扫读效率高。
- 12 个账号的规模下最顺手，适合当前系统。
- 角色说明完整展示，管理员能直接判断权限边界。

**注意：**

- 窄屏（< 780px）会自动堆叠成上下结构。
- 账号超过 30–50 个后，列表需要分页和更复杂的筛选。

---

## 方案 B：表格 + 侧滑抽屉（已采用）

![方案 B：表格 + 侧滑抽屉](./design/user-management/user-b.png)

**结构：**

- 全宽表格：搜索、角色/状态筛选、批量禁用、分页。
- 点击用户行，右侧滑出「用户详情」抽屉。
- 抽屉内包含基础信息、角色、生效权限和保存操作。

**优点：**

- 表格保留完整列，适合账号增长和批量操作。
- 抽屉按需出现，不占用列表空间。
- 详情内容更紧凑，角色只显示名称和人数，减少抽屉高度。
- 后续扩展部门、最后登录、登录方式等列更容易。

**注意：**

- 同时对比多个用户时需要反复开关抽屉。
- 窄屏下抽屉会覆盖表格，需要保证关闭入口明显。

---

## 采用结论

| 场景 | 建议 |
| --- | --- |
| 当前用户管理页 | **方案 B（表格 + 抽屉，已采用）** |
| 12 个账号 / 更重视详情常驻 | **方案 A（主从列表）** |
| 审计视角查看用户与角色 | 保留 B 的表格列，详情继续用抽屉 |

当前已采用 **B 作为用户管理默认页**，并合入 `ui-design.html`：

- 表格保留完整列，便于账号增长、批量禁用和快速扫读。
- 点击用户行从右侧滑出详情，抽屉按需出现，不长期占用表格空间。
- 抽屉内角色只显示名称和人数，减少高度；权限摘要和保存操作保持可见。
- 后续账号继续增长时，表格结构更容易扩展。

## 两套方案对比

| 维度 | A 主从列表 | B 表格 + 抽屉 |
| --- | --- | --- |
| 详情可见性 | 始终可见 | 按需打开 |
| 扫读效率 | ★★★★☆ | ★★★★★ |
| 单用户编辑效率 | ★★★★★ | ★★★★☆ |
| 账号增长扩展性 | ★★★☆☆ | ★★★★★ |
| 批量操作 | ★★☆☆☆ | ★★★★★ |
| 视觉轻量 | ★★★★★ | ★★★★☆ |
| 推荐定位 | 当前规模默认 | 增长后备选 |

## 落地对应

| 设计元素 | 前端实现建议 |
| --- | --- |
| 用户列表 / 表格 | `GET /users` 分页 + 关键字/角色/状态筛选 |
| 详情面板 / 抽屉 | 选中用户后加载 `GET /users/{id}`，角色与权限一并返回 |
| 角色勾选 | `PUT /users/{id}/roles` 全量覆盖，保存前显示 diff |
| 重置密码 | `POST /users/{id}/reset-password`，强制首次改密 |
| 禁用 / 启用 | `PATCH /users/{id}`，成功后 `token_version += 1` |
| 批量禁用 | 逐条调用或新增批量接口，需二次确认 |
| 权限校验 | 前端 `SYSTEM_ADMIN` 入口 + 后端 `user:read` / `user:write` 双重限制 |
