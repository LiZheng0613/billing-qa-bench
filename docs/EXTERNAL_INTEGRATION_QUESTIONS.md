## 1. EXT-01 Cypher 执行器工具

### 1.1 已冻结的 Mock 契约（v0.1）

平台按以下四个端点实现客户端，Mock 见 `backend/tests/mocks/cypher_tool_mock.py`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/execute` | 执行参数化只读 Cypher |
| `GET` | `/logs` | 按 `session_id` 增量拉取工具调用日志 |
| `GET` | `/health` | 探活 |
| `GET` | `/meta` | 版本、限额与能力元信息 |

`POST /execute` 请求体：

```json
{
  "session_id": "uuid-or-null",
  "query": "MATCH ... RETURN ...",
  "params": {"order_no": "A2024001"},
  "max_rows": 200,
  "timeout_ms": 10000
}
```

成功响应：

```json
{
  "code": "OK",
  "data": {
    "columns": [{"name": "amount"}],
    "rows": [{"amount": 12345.67}],
    "row_count": 1,
    "truncated": false,
    "elapsed_ms": 12.3,
    "query_id": "q-...",
    "executor_version": "1.0.0"
  }
}
```

已冻结的九种错误码：`INVALID_REQUEST`、`PARAM_MISSING`、`QUERY_SYNTAX`、`QUERY_FORBIDDEN`、
`TIMEOUT`、`TOOL_UNAVAILABLE`、`ROW_LIMIT_EXCEEDED`、`SESSION_NOT_FOUND`、`INTERNAL_ERROR`。

### 1.2 需要客户 / 执行器团队确认

1. **真实地址与网络**
   - 生产 / 测试环境 endpoint 分别是什么？是否需要通过网关域名访问？
   - 平台服务器到执行器是否需要固定 IP 白名单、专线、VPN 或正向代理？
   - 是否支持 HTTPS？证书由谁签发、是否需要客户端证书（mTLS）？
2. **鉴权方式**
   - 使用静态 Token、OAuth2 Client Credentials、HMAC 签名、mTLS，还是网关注入身份？
   - Token 有效期、刷新方式、失效错误码分别是什么？
   - 平台侧 `auth_config.headers` 是否可以承载全部鉴权信息？是否需要动态签名插件？
3. **契约确认**
   - 上述 v0.1 字段是否全部保留？是否允许新增字段而不破坏兼容？
   - `code` 成功值是否固定为 `"OK"`？是否存在 `code=0` / `success=true` 等其他形态？
   - 多语句、事务、`CALL` 子查询是否允许？只读策略具体拦截哪些关键字？
   - `max_rows` / `timeout_ms` 上限是多少？超限返回 `ROW_LIMIT_EXCEEDED` 还是 `INVALID_REQUEST`？
4. **参数绑定**
   - 参数占位符是 `$name`、`{name}` 还是其他形式？平台当前按 `$param` 生成模板。
   - 参数类型是否支持数组、日期、布尔？空值如何处理？
5. **日志与审计**
   - `/logs` 的 `seq` 是否单调递增？跨会话是否唯一？
   - 日志保留时长、是否包含完整 query 与 params、是否可直接用于取证？
   - 平台是否可以在日志中写入 `trace_uid` 以便关联一次评测？
6. **只读防护**
   - 工具侧是否已强制只读账号？是否禁止 `CALL` 动态过程与 APOC 写过程？
   - 平台侧会在剔除字符串字面量后扫描写关键字；工具侧是否采用相同或更严格规则？
7. **版本与限额**
   - `/meta` 返回哪些字段？`executor_version` 是否可用于判分结果溯源？
   - 单租户并发上限、QPS 上限、单次最大返回字节数是多少？

## 5. EXT-05 Agent 目标 API

平台已支持环境级 `base_url`、`api_path`、`headers_template`、`body_template`、
`extractors`（JSONPath）、流式 / 非流式与 Pre-Hook 鉴权。需要确认：

### 5.1 报文模板与用例级参数注入（平台已实现）

- 报文格式由环境模板固定：`headers_template` / `body_template` 中使用 `{{variable}}` 占位符；
  具体取值按用例不同，由用例级 `request_variables`（key-value，值支持字符串 / 数字 / JSON）注入。
- 变量合并优先级：运行时变量（`query` / `session_id` / `history` / `history_text` / `turn`）
  \> 用例 `request_variables` > 环境变量池。
- 对接方只需确认「哪些字段需要按用例变化」，平台即可在用例中配置，无需为新参数改代码。
- 接口配置页提供**报文预览**（选一条示例用例，只读渲染 headers/body 并标注每个变量的来源），
  可用于与 Agent 平台逐字段核对。

### 5.2 多轮会话绑定（两种模式均保留，可配置）

会话值的**生成方尚未确定**，因此平台同时支持两种模式，环境级默认 + 用例级可覆盖：

| 模式 | 配置位置 | 行为 |
| --- | --- | --- |
| `SERVER_RETURNED` | 环境 `session_mode`（默认） | 首轮不传会话值，平台从响应中提取并回填，后续轮次沿用 |
| `CLIENT_GENERATED` | 环境 `session_mode` | 执行开始时由平台生成唯一值（`exec-{execution_id}-xxxxxxxx`），全程各轮携带 |
| `INHERIT` | 用例 `session_mode`（默认） | 跟随环境配置 |
| `FIXED` | 用例 `request_variables.session_id` | 使用显式固定值，优先级最高（用于复现特定会话 / 调试） |

会话字段名**由模板占位符位置决定**，平台不写死字段名。例如：

```json
{
  "query": "{{query}}",
  "conversationId": "{{session_id}}",
  "history": "{{history}}"
}
```

对接时需确认：

1. **会话由谁生成**：目标接口是否在响应中返回会话值？字段路径是什么（`$.data.session_id` 等）？
   若不返回，应切换为 `CLIENT_GENERATED`。
2. **字段名与位置**：会话值放在 body 哪个字段（`session_id` / `sessionId` / `conversationId` / 嵌套对象），
   还是放在 Header / Query？请给出完整示例报文。
3. **多轮上下文**：目标接口是依赖会话值维护上下文，还是要求每轮显式传 `history`？两者是否可混用？
4. **会话生命周期**：超时时间、最大轮次、并发隔离规则；同一会话值被并发复用时是否互相污染？
5. **固定会话**：是否允许平台指定会话值（`FIXED` 模式）？是否有格式校验或白名单？
6. **错误信号**：会话缺失 / 过期 / 非法时返回什么状态码与错误体？平台据此区分 `ENV` 与 `BUSINESS` 失败。

### 5.3 其余待确认项

1. **请求契约**
   - 最终请求方法、路径、Header、Body 模板是否与 Mock 一致？
   - `session_id`、`history`、`query` 的字段名与嵌套结构？
   - 是否支持多轮会话？会话超时时间？
2. **响应契约**
   - 最终答案在哪个 JSONPath？是否可能出现在多个候选字段？
   - 流式响应的事件格式（SSE `data:` / JSON Lines / 自定义分隔符）？
   - `session_id`、`intent`、`generated_sql`、`api_params`、`raw_db_data` 是否稳定返回？
3. **错误与重试**
   - 业务错误、限流、超时、空响应的 HTTP 状态码与错误体结构？
   - 哪些错误允许平台自动重试？重试是否会重复扣费或产生副作用？
4. **幂等与追踪**
   - 是否支持传入 `trace_uid` / `request_id` 用于全链路追踪？
   - 同一请求重复调用是否幂等？
5. **鉴权**
   - 使用 Bearer Token、Cookie、AK/SK、OAuth2 还是网关注入？
   - Pre-Hook 获取 Token 的接口、返回结构、缓存时长是否与 Mock 一致？
6. **Agent 平台侧限制**
   - 单租户 QPS / 并发 / 日调用量上限？
   - 是否允许评测平台在生产环境执行只读问答？是否需要独立评测租户？

## 6. EXT-06 `tool_calls` 轨迹 schema

轨迹权重为 0，仅用于根因定位。平台已支持把每轮工具调用写入 `turn_trace.tool_calls`。

请确认每个工具调用至少提供：

| 字段 | 说明 | 是否必需 |
| --- | --- | --- |
| `seq` | 轮内调用序号 | 是 |
| `kind` | `CYPHER` / `SQL` / `API` / `CALC` | 是 |
| `capability` | 能力 key（若 Agent 侧有） | 否 |
| `query` | 实际查询语句或接口路径 | 是 |
| `params` | 绑定参数 | 否 |
| `status` | `SUCCESS` / `FAILED` / `TIMEOUT` / `DENIED` | 是 |
| `rows` / `row_count` | 返回行数 | 否 |
| `elapsed_ms` | 耗时 | 否 |
| `error` | 错误信息 | 否 |
| `started_at` | 调用开始时间 | 否 |

需要确认：

1. 这些字段由 Agent 平台直接返回，还是平台通过执行器 `/logs` 补齐？
2. 工具调用与对话轮次的关联键是什么（`session_id` + `seq` + 时间）？
3. 是否包含完整 query？若包含敏感信息，是否需要脱敏后再落库？
4. 失败调用是否也返回？`DENIED` 的具体含义是什么？
5. 是否存在并行工具调用？如何排序与去重？
